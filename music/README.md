# ミュージック — 自分用のオフライン音楽プレイヤー

端末の中の音楽ファイルを**入れるだけ**で、通信なしで聴けるアプリです。
見た目は、すりガラスのように透ける浮いたバーと丸いボタンの、リキッドグラス風です（絵やアイコンは自作です）。
明るい画面・暗い画面は、端末の設定に合わせて切りかわります。

- **登録・通信・広告なし**。曲はこの端末のブラウザの中だけに保存され、どこにも送りません
- **入れた曲はオフラインで聴ける**。アプリ本体も端末に控えるので、圏外でも開けます
- **すぐ出る**。起動のときは曲の情報だけを読み、一覧は見えている行だけを作ります（曲が何千あっても同じ速さ）
- ビルド不要の静的サイト。ライブラリや CDN は使っていません

## 使う人へ

### iPhone・iPad で使う

1. **Safari** でこのページを開く
2. 共有ボタン（□に↑）→ **「ホーム画面に追加」**
3. 通信できるうちに、ホーム画面にできた「ミュージック」のアイコンから一度開く（これで、次からは通信なしで開けます）
4. 左上の **＋** を押し、出てきた中から **「ファイルを選択」** を選んで、「ファイル」アプリの中の音楽を選ぶ

> **曲はホーム画面のアイコンから開いて入れてください。**
> Safari で開いたときと、ホーム画面のアイコンから開いたときでは、保存場所が別々です。
> また、Safari のタブのままだと、しばらく使わないうちにブラウザが保存データを片づけてしまうことがあります。

- 音楽ファイルは、先に「ファイル」アプリ（この iPhone 内・iCloud Drive など）に入れておきます。
  パソコンからは、AirDrop・iCloud Drive・USB ケーブル（Finder / iTunes の「ファイル共有」）などで送れます
- 選べるのは「ファイル」アプリにある音楽ファイルです。「ミュージック」アプリ（Apple Music）の中の曲は選べません
- とても多いときは、**数十曲ずつ**に分けて入れると確実です。読み込みが終わるまで、アプリを閉じたり切りかえたりしないでください。
  「読み込めなかったファイル」が出たら、同じものをもう一度選べば、入っていない曲だけが入ります
- 音量は、本体の音量ボタンで変えます

### パソコンで使う

ブラウザで開いて、ファイルやフォルダを**画面にドラッグして落とす**だけです（＋ からも選べます）。
タグのない曲は、`アーティスト/アルバム/01 曲名.mp3` のようなフォルダ名・ファイル名から題名などを補います。

### 画面と操作

| 場所 | できること |
|---|---|
| 下のタブ（浮いているガラスのバー） | プレイリスト／アーティスト／曲／アルバム／その他。同じタブをもう一度押すと最初の一覧にもどる |
| 一覧 | 曲を押すと再生。「再生」「シャッフル」のボタンで、その一覧をまとめて流す。右はしの「あ か さ … A B C …」をなぞると、その頭文字へ飛ぶ |
| 下に浮かぶ「いまの曲」 | 押すと再生中の画面が開く。再生・一時停止と「次へ」はここからも押せる |
| 行を横になぞる | 「削除」ボタンが出る（アプリの中から消えるだけで、元のファイルは消えません） |
| 行を長押し（パソコンは右クリック） | 「次に再生」「プレイリストに追加」「削除」 |
| 再生中の画面 | ジャケットの色がにじむ背景の上に、再生位置のつまみ・前へ／再生・一時停止／次へ・シャッフル・リピート。右上のボタンでジャケットが裏返り、これから流れる順番が出る。左上の ∨ で閉じる |
| スマホを横向きにする | ジャケットが横に流れる画面。まんなかのジャケットを押すと裏返って曲が選べる |
| ロック画面・イヤホン | 画面を消しても再生は続き、ロック画面やイヤホンのボタンで操作できる |
| その他 → 保存容量 | 曲の数・使っている容量。「すべての曲を削除」もここ |

- **プレイリスト**：「新規プレイリスト…」で名前を付け、曲を選んで「完了」。中の「編集」で、はずす・並べかえができます
- **前回の続きから**：閉じても、次に開いたとき同じ曲の同じ位置から聴けます
- **歌詞**：ファイルに歌詞が入っていれば、再生中の画面のジャケットの上に出ます（ジャケットか、歌詞のボタンを押すと出し入れ）

### 聴ける形式

MP3 / AAC・Apple ロスレス（.m4a）/ FLAC / WAV / AIFF は iPhone・iPad で聴けます。
Ogg Vorbis・Opus は端末やブラウザによります（「その他 → 使い方」の一番下に、その端末で聴ける形式が出ます）。
聴けない形式のファイルは、取り込みのときに自動でとばして、あとで件数を知らせます。

### 曲が消えるのはどんなとき

曲はブラウザの保存領域（IndexedDB）に入っています。次のときに消えます（**元のファイルは消えません。元のファイルは取っておいてください**）。

- ホーム画面のアイコンを削除したとき
- 設定 → Safari →「履歴と Web サイトデータを消去」などで、このサイトのデータを消したとき
- 端末の空きがとても少なくなって、端末が自動で片づけたとき
- 「その他 → 保存容量 → すべての曲を削除」をしたとき
- プライベートブラウズで入れた曲（閉じると消えます）

## 置き場所（公開のしかた）

**公開先： https://ngcmwbj-art.github.io/-/music/**

オフラインで使うには、**https で始まるアドレス**に置く必要があります（Service Worker の決まりです）。
このリポジトリの GitHub Pages は `claude/kei-truck-runner-game-ngc2ni` ブランチの中身を公開しているので、
そのブランチに `music/` フォルダを入れると、上のアドレスで開けます。

開発は別のブランチでして、できあがった `music/` をそのまま公開元のブランチへ写します。

```sh
# 公開元のブランチに、開発ブランチの music/ を写して push する
git fetch origin claude/kei-truck-runner-game-ngc2ni
git worktree add -B claude/kei-truck-runner-game-ngc2ni ../pages origin/claude/kei-truck-runner-game-ngc2ni
cd ../pages
git rm -r -q --ignore-unmatch music && git checkout <開発ブランチ> -- music
git commit -m "ミュージック：…" && git push origin claude/kei-truck-runner-game-ngc2ni
```

push すると 1 分ほどで公開されます。使う側は、アプリを一度完全に閉じて開きなおすと新しい版になります。

手元で試すとき：

```sh
cd music
node tests/serve.mjs 8765      # → http://127.0.0.1:8765/
```

### 速さとオフラインのための工夫

- **起動**：読むのは曲の情報（数百バイト／曲）だけ。音声ファイル本体には触りません
- **一覧**：見えているあたりの行だけを作り、スクロールに合わせて入れかえます
- **取り込み**：タグは必要な部分だけを読みます（1曲 数ミリ秒）。本体は保存のときに 8MB ずつ読みます
- **再生**：となりの曲（次・前）のファイルを先に取り出しておき、曲が終わった瞬間や、
  ロック画面で「次へ」「前へ」を押した瞬間に、待ちなしで切りかえます。
  画面を消しているあいだも次の曲へ進めるように、`<audio>` は1つだけを使い回します
- **日本語**：よみがなのタグ（iTunes で取り込んだ曲に入っています）があれば五十音順に並びます。
  昔の MP3 に多い Shift_JIS のタグも読めます。全角・半角、カタカナ・ひらがなを区別せずに検索できます

### iPhone のための備え

実機では確かめられていないので、iOS の Safari について分かっている不具合を調べ、どの版でも動くほうの書き方を選んでいます。

| 備え | 理由 |
|---|---|
| 音声とジャケットを `Blob` ではなく `ArrayBuffer` で保存する | IndexedDB に入れた Blob を「保存できない・読み出せない・再生できない」不具合が、版をまたいで何度も報告されている |
| 画面を消している間は、曲の終わりのほんの少し手前（約 0.08 秒前）で次の曲へ切りかえる | ホーム画面のアプリで「曲を最後まで流しきると、裏では次の曲を鳴らしはじめられない」という報告がある |
| 最初のタップの中で、無音の短い音を一度鳴らす | iPhone では、タップの流れの中で一度 `play()` した `<audio>` だけが、そのあとタップなしで鳴らせる |
| ロック画面のジャケットを、Service Worker が返すふつうの URL で渡す | `blob:` や `data:` の絵は出ないことがある、という報告がある |
| 「10秒もどる・すすむ」を登録しない | 登録すると、ロック画面の「前の曲・次の曲」ボタンが出なくなる |
| iPhone ではファイル選びの種類の指定（`accept`）を外す | 指定があると、音楽ファイルが灰色になって選べない版がある |
| つまみ（再生位置・音量）を自作する | 標準のつまみは、線の上を押しても動かない・つかみにくい |
| 続きの位置を `localStorage` にも控える | 裏に回る直前の IndexedDB への書き込みは、間に合わないことがある |
| 画面の切りかえに History API を使わない | 使うと、画面の端からのスワイプで iOS の「戻る」が働き、動きが二重になる |

### 保存データ（IndexedDB `music-box`）

| 入れ物 | 中身 |
|---|---|
| `tracks` | 曲の情報（題名・アーティスト・アルバム・長さ・再生回数など） |
| `files` | 音声ファイルの中身（8MB ずつの ArrayBuffer。キーは `[曲の id, 何番目か]`） |
| `art` | ジャケット画像（小・中・大。ArrayBuffer） |
| `lyrics` | 歌詞 |
| `playlists` | プレイリスト |
| `kv` | 設定と「前回どこまで聴いたか」 |

「前回どこまで聴いたか」は `localStorage` の `music.pos` にも控えています。

## 手を入れたとき

アプリのファイル（`index.html`・`css/`・`js/`・`icons/`）を変えたら、**必ず**次を流してください。
`sw.js` の中の版の印が変わり、次に開いたときに新しい版へ入れかわります（流し忘れるとテストが落ちます）。

```sh
cd music
node tools/build-sw.mjs
npm test            # 単体テスト（タグ読み・ライブラリ・sw.js が最新か）＋ 画面を動かすテスト
```

- 単体テスト：`node --test "tests/unit/*.test.mjs"`
- 画面を動かすテスト：`node tests/e2e/run-all.mjs`（Playwright の Chromium で実際に操作します）
  - `app.check.mjs`：取り込み → 一覧 → 再生 → 次の曲 → 開きなおし → 削除 → プレイリスト → 検索 → 通信なしでの起動
  - `player.check.mjs`：連打・シャッフル・再生中の削除などで再生エンジンを揺さぶり、状態がずれないかを確かめる
  - `coverflow.check.mjs`：横向きのジャケットの流れ
- テスト用の小さな音源は `tests/fixtures/`（作り方は `tests/make-fixtures.sh`）

## 分かっている制限

- **iPhone では、アプリから音量を変えられません**（本体のボタンで変えます）。音量のつまみは、変えられる端末でだけ出ます
- 曲と曲のあいだに、ごく短い無音が入ります（ギャップレス再生ではありません）。
  iPhone では、画面を消している間だけ、曲の終わりのごく短い部分（約 0.08 秒）をとばして次へ進みます
- よみがなのタグが無い漢字の題名は、見出し「#」にまとまります
- 更新を反映するには、アプリを一度完全に閉じて開きなおします（開いたままだと古い版のままです）
- Ogg Vorbis・Opus は、iOS 18.4 より前では聴けません
- 1つ 200MB をこえるファイルは入れられません（再生のときに1曲ぶんをメモリに広げるため）
- iOS 16 以前のホーム画面アプリは、保存できる合計がおよそ 1GB までです（17 以降はずっと多く入ります）
- iOS そのものの不具合で、アプリ側では直せないものがあります
  - iOS 26.0〜26.1：ホーム画面のアプリを開きなおしたあと、音が出ないことがある（iOS を更新してください）
  - iOS 15.0〜15.3：ホーム画面のアプリは、画面を消すと再生が止まる
