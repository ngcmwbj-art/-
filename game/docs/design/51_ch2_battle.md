## 2. 第1章からの変更点と調整点

★（00_concept）は変えていない。第1章の禁止リスト（00 16章）はすべて守る。

| # | 変更・調整 | 理由 |
|---|---|---|
| 1 | レベル上限を `flag_ch2_started=1` のあいだ **7** にする。定数 `LEVEL_CAP` を関数 `levelCap()` にする | 50 1.6。第1章の遊びなおし（はじめる）では5のまま |
| 2 | 第2章に入るときの経験値の下限を150にし、**レベルは経験値から計算しなおす**。第1章でたくさん戦った人（累計230以上。最大275）は、プロローグで Lv6 になる | 第1章の上限5で止まっていた経験値を、上限が上がった瞬間にむだにしない。第1章の寄り道のごほうび |
| 3 | 第2章の敵の技の「！」の台詞は、**初戦でも技に結びついた台詞を優先する**（20 10.3 の選び方の1が4より先） | 第2章は、台詞がその技でしか意味を持たないもの（「曲がれるんかい！」「リズム 正確すぎ！」）が多い。1番が場違いな技で出るのを防ぐ。1番に結びついた技を各敵の最初の行動にしたので、ほとんどの敵は初戦の最初のツッコミが1番になる（ヨビモドシとチョトツだけ例外） |
| 4 | スネトマト②を**2体組**にした（房） | 第2章の戦闘は1体ずつが多く、Lv7 の報酬「はみだしペケ」（となりの敵に半分）の出番がない。トマトは房でなる。第1章のコーンの2体組と同じ手触りも1つ入る |
| 5 | Lv7 のはみだしペケは、**となりに敵がいないとき、同じ敵にもう0.25倍**当たる | 第2章は1体の戦闘がほとんどで、報酬が空振りになる。「はみだす」の見た目のまま、1体でも得がある形 |
| 6 | 「トマトをかかげる」は**優先度+2**（まもると同じ）で、そのラウンドのほかの行動より先に明るくなる | カネナリくんがかかげれば、同じラウンドのミナトの「みました」がラッパに届く。2人で1つの仕事をする形になり、明るい2ラウンドを2回とも部位破壊に使える |
| 7 | ボス戦の部位破壊の固定ダメージを **50×判定倍率**（くっきり75／ふつう50／かすれ35）にする（第1章は40） | 第2章のレベルでは、たたく1回が30〜40。40のままだと部位破壊が「ふつうの攻撃1回ぶん」に埋もれ、見てあげる手間に見合わない |

## 4. 計算式の追加

20 4章の式はそのまま。ここに書くものだけ足す。

### 4.1 ダメージの式に足すもの

```
まもり実効 = まもり × (1 + 0.25 × まもり段階)
           × (みられている ? みました係数 : 1)
           × (ひらいている ? 1.5 : 1)
           × (すねている ? 2.5 : 1)          // 第2章：status_sune
```

- すねている（2.5倍）はみましたと重ならない（みましたで解けるので）。
- 行動順（20 4.8）のすばやさに `buff_spd` の段階を掛ける：`すばやさ × (1 + 0.25 × すばやさ段階) × 乱数(0.9〜1.1)`。逃走の式（20 4.6）の敵の最高すばやさにも同じく掛ける。

### 4.2 固定ダメージ（第2章で足すもの。乱数0.9〜1.1だけ掛ける）

| もの | 値 |
|---|---|
| 部位破壊（ヨビモドシのラッパ） | 50 × 判定倍率（くっきり75、ふつう50、かすれ35） |
| 夜ふかし | ボスのちから実効（段階込み。ごあいさつで下がる）× 3 − 対象のまもり × 0.5。ツッコミ、まもるで半減（重なる） |
| 感電（ビリビリ番） | 3（ビリビリ番のちからが+1段階以上なら5）。**乱数なし**。HPは1で止まる |
| はみだしペケ | 本体へのダメージ × 0.5（となり）または × 0.25（同じ敵）。乱数は掛けなおさない |
| 徹夜の回復（テツヤ） | HP+10（固定。最大HPで止まる） |

### 4.3 おつかれさまの成否

```
成功率 = くっきり 100% ／ ふつう 75% ／ かすれ 50%     // うんは関係しない
テツヤ：判定に関係なく 100%
ボス（ヨビモドシ）：0%（効かない。朱肉とターンは使う）
休憩あけのラウンドの敵：選べない（対象の一覧で灰色。選ぶと 22章 #9 の1ページ、ターン消費なし）
休憩中の敵：選べない（同じく灰色）
```

### 4.4 状態異常の成否（第2章の技）

20 4.4 と同じ（`基本確率 × (1 − 対象のうん / 100)`、ツッコミ成功なら0%）。例外は `status_henji`：おなまえ よびだしの**ツッコミに失敗したら必ず**かかる（うんで防げない。「つい返事をしかける」のは運ではないので）。

## 18. 実装向けのデータ構造と公開API（差分）

### 18.1 データの形（`src/data/battle/types.ts` に足すもの）

```ts
// EnemyDef に足す
interface EnemyDef {
  // ...第1章のまま
  /** 戦闘のはじめにかかっている状態（'status_sune' | 'status_tetsuya'）。 */
  startStatus?: string[];
  /** 打のヒットで攻撃した人が受ける固定ダメージ（ビリビリ番：3、ちから+1以上で5）。 */
  shock?: { base: number; charged: number };
  /** 撃破の型。既定 'restore'（思いだす）。'fly'＝セミ、'runaway'＝チョトツ（山へ帰る）。 */
  defeatStyle?: 'restore' | 'fly' | 'runaway';
  /** おつかれさまで休む回数（既定1、テツヤ2）。0＝効かない（ボス）。 */
  restActions?: number;
  /** おつかれさまが判定に関係なく必ず成功する（テツヤ）。 */
  restAlways?: boolean;
  /** 部位（ボスごと）。 */
  parts?: BossPartDef[];
}

// 敵の状態（src/battle/model.ts の EnemyStatus）に足す
interface EnemyStatus {
  // ...第1章のまま
  sune?: boolean;                 // status_sune
  tetsuya?: boolean;              // status_tetsuya
  kyuukei?: number;               // 休む残りの回数
  restImmuneRound?: number;       // このラウンドはおつかれさまが効かない
  stareAt?: string;               // チョトツ：溜めでにらんでいる Member.id
}

// 能力段階に spd を足す
interface Stages { atk: Stage; def: Stage; hit: Stage; spd: Stage }

// ItemDef に足す
interface ItemDef {
  // ...第1章のまま
  special?: 'kinakobou' | 'shippu' | 'capsule' | 'tomato' | 'umeboshi';
  /** 大事なものだが、このボスの戦闘では使える（はなまるトマト）。 */
  usableInBattleWith?: string[];   // ['boss_yobimodoshi']
  /** 行動順の優先度（トマト：2）。 */
  priority?: number;
}
```

- 味方の状態 `status_henji` は `Member.status` に入れる。とおせんぼと同じ「1回の行動を失う」の組（`blocked_<id>` のメモで、飛ばしたラウンドの終わりに消す。`src/battle/flow.ts` の `status_tsukamare` `status_toosenbo` の処理に並べる）。`PartyUnit.canAct` に `status_henji` を足す。
- ボスの部位：`BOSS_PARTS` を `Record<bossId, BossPartDef[]>` にする（`boss_omukaemachi` と `boss_yobimodoshi`）。ヨビモドシの部位は「光る部位が次のラウンドの最後に行動する」（第1章）ではなく「明るいときだけ破壊できる。部位は行動しない（技はボス本体のAIが選ぶ）」。
- ボスの付箋（鐘／名札）は同じ部品で、アイコンの種類だけ変える（`'bell' | 'nametag'`）。
