【あなたの担当: ワールド（フィールド）エンジン＋町の外マップのレベルデザインと環境アート】
担当ディレクトリ: src/world/**, src/art/tiles/**, src/art/props/**, src/data/maps/**（src/world/index.ts を含む）
主な参照: docs/design/00_concept.md（3章 舞台・段階システム・光と色・マップ密度、6.11 エンカウント、11章 ふしぎ）, docs/design/30_level_art.md（最重要）, 10_narrative.md（NPC配置・調べるテキスト）, 20_systems_battle.md（フィールド上の敵の動き）, 01_index.md

実装するもの:
1. フィールドシーン（registerScene('field', ...)。URLで ?scene=field&map=<id>&x=<tx>&y=<ty>&stage=<n> を受け付ける）
2. マップデータ形式（src/data/maps/ に TypeScript で記述。ASCIIレイヤー＋オブジェクト配置リスト。人間が編集しやすいこと）とローダー
3. タイル／地形のドット絵（src/art/tiles/）：アスファルト、歩道、白線とかすれ、横断歩道、ブロック塀、砂利、土、草地、植え込み、側溝、線路とバラスト、アーケードの床、公園の土、駐車場など。hash2 等で位置ごとの変種（ひび、汚れ、雑草、落ち葉、マンホール、水たまり）を必ず混ぜ、同じタイルが一直線に6枚以上並んで見えないこと。境界はオートタイルでなめらかにつなぐ
4. 建物・小物（src/art/props/）：瓦屋根の家、商店（肉のマルヤマ、駄菓子ひのや、豆腐まめ吉、コインランドリー、写真館、シャッター店、交番）、半透明の波板アーケード屋根（夕日の縞が床に落ちる）、モール外観、時計塔、カバの遊具、防災無線スピーカー柱、電柱と電線（タイルをまたいで張る）、自販機、カーブミラー、お地蔵さん、ブランコ、砂場、水飲み場、公衆トイレ、ベンチ、のぼり旗、ガチャ台、室外機、物干し、植木鉢（家ごとに違う）、自転車、郵便受け、表札、看板、遮断機と警報機、車止め、のらカート等。30_level_art.mdの小物リスト（60種以上）を実装。各小物は左上ハイライト・左縁リムライト・東へ伸びる影・色付きアウトライン（外周 #2A2440 系）を持つ
5. レンダリング：静的な地面はチャンク単位でオフスクリーンに焼く。キャラと小物は足元Yでソート。前景レイヤー（屋根、木の上部、電線、アーケード屋根）はキャラの上。動く物（揺れる草、のぼり、電線の鳥、猫のしっぽ、蛍光灯のちらつき、自販機の明かり、ヒグラシの木の揺れ等）を1画面に3つ以上
6. 空・光・影と「段階システム」（stage 0/1/2/夜）：setStage(n) で空のグラデ、全体の色味、影の長さと向き（段階2では全影が北東）、小物の差し替え、NPCや敵シンボルの出現条件を一括で切り替える。段階は game state のフラグで保持。17:00の瞬間の演出（全画面の縦方向正弦波の揺れ0.8秒、色温度0.6秒遷移）用のフックも用意（トリガーするのはシナリオチーム）
7. プレイヤー操作：8方向移動（通常4.5タイル/秒、ダッシュ7タイル/秒）、サブピクセル移動でも描画は整数、壁ずり（角で引っかからない）、決定で向いている方向を調べる／話す、足音SE（sfx('se_step_*')等。IDは40_audio.mdに合わせる）、カメラ追従（先読み、マップ端でクランプ）、相棒（カネナリくん）が加入後は後ろをついて歩く（軌跡追従）
8. 出入口とマップ遷移（フェード＋SE）。屋内マップは次のラウンドで別チームが作るので、ドアの接続先IDは設計書どおりに置き、未作成のマップへのワープは「鍵がかかっている」等にせず、マップ登録が無い場合はデバッグログのみにしておく。ただし**ミナトの家（2F自室・1F）は今回あなたが作る**（ゲームの開始地点なので）
9. エンティティ：NPC（charSprite(id) で描画。向き、うろうろ、首振り、段階ごとの出現条件、話しかけると向き直る）、調べられる物（テキストは10_narrative.mdから入れる）、「ふしぎ」（11章）、イベントトリガー領域、フィールドの敵シンボル（6.11の動き、背後からの接触判定→initiative、startBattle呼び出し、勝利後はその場に「もとにもどった物」charSprite('restored_<enemy_id>') を残し、以後復活しない）
10. スクリプトAPI（src/world/api.ts）：シナリオチームがイベントを書くためのAPI。registerScript(id, fn) でNPC会話・調べる・トリガー・カットシーンのスクリプトを登録でき、NPC/オブジェクトは scriptId で参照する（スクリプト未登録なら配置データのテキストで会話）。APIには少なくとも：アクター取得、歩かせる（タイル経路）、向き、エモート（src/art/chars/emotes.ts の emoteFrames）、ジャンプ、カメラのパン/戻す、プレイヤー操作ロック、ワープ、段階変更、フラグ、アイテム付与、アクターの出現/消去、画面効果（game.shake/flash/fadeOut/fadeIn）、BGM/環境音、wait。会話は ui/dialog.ts の say/choose をそのまま使う
11. デバッグコマンド: warp(map,x,y), stage(n), noclip(on), collision(on)（当たり判定の表示）, where()
12. 起動シーン：まだタイトル画面は無いので、boot.ts のデフォルト 'title' が未登録の間は field が選ばれるよう、あなたの world/index.ts で registerScene('field', …) すること（'title' はUIチームが後で登録する）

キャラスプライトは src/art/chars/index.ts の charSprite(id) を使う（キャラアートチームが並行して登録中。未登録IDはフォールバック表示になる）。IDは設計書のNPC IDを使う。
戦闘は battle/api.ts の startBattle を使う（バトルチームが並行して実装中）。
目視確認：町の各エリアのスクリーンショット（段階0/1/2で同じ場所）を撮り、MOTHER2や市販の16bit風インディーRPGの町と比べて、情報密度・色彩・生活感・同じ素材の繰り返しが無いかを厳しく評価して改善すること。
