# game-dev

内容：$ARGUMENTS

1. **仕様確認**：docs/game/design.md から、関係する設計書（docs/design/）を読む。採用済みの案なら docs/ideas/ の依頼主の変更も読む。決まっていない所は聞く。
2. **実装**：.claude/rules/game.md に従う。表示名を変えても ID は変えない。画面の文は日本語・1ページ3行まで。
3. **ローカル起動**：開発サーバー（127.0.0.1:5173）を起動して、変えた場面へ `__game.cmd.warp` や `jump` で行く。
4. **確認**（docs/game/devices.md の画面サイズで）：
   - PC 1280×720（キーボード）
   - iPad 横 1210×654・1000×540（タッチ。ボタンに中身がかからないか）、iPad 縦 820×1100
   - スマホ横 844×390・縦 390×844（タッチ）
   - 型チェック、`textcheck2()`・`wrapCheck()`、関係する通しテスト（2本同時に走らせない）
   - 実機（iPad・iPhone の Safari）でしか分からない所は「未確認」と書き、依頼主に見てほしい所として挙げる。
5. **不具合の記録**：見つけた不具合で今回直さない物は docs/game/bugs.md に、症状・再現手順・端末を書く。
6. 報告と引き継ぎ：変えた所、検査の結果、写真があれば写真、見てほしい所。
