# project-work

依頼：$ARGUMENTS

1. **資料確認**：AGENTS.md の参照先から、依頼に関係する物だけ読む（tasks/active.md、docs/ai/context.md、該当する設計書）。対象・完成条件・変更しない範囲を1〜3行で書き出す。分からない点があれば、推測で埋めずに聞く。
2. **計画**：変更が小さい（数行〜1ファイル）なら計画は省き、すぐ 3 へ。大きいときだけ、手順を3〜6行で示す。
3. **小さく実行**：必要な所だけ変える。既存の書き方に合わせる。
4. **検査**：docs/ai/checks.md から関係する検査を選んで実行する。実行できなかった物は「未実行」とその理由を書く。
5. **修正**：失敗したら原因を直して 4 に戻る。
   - 止める条件（このプロジェクトの運用の上限）：同じ失敗が2回続いた、または修正が3巡に達したら、それ以上は進めない。原因の見立てと足りない情報を tasks/handoff.md に書き、依頼主に報告する。
6. **引き継ぎ**：長い作業なら tasks/active.md と tasks/handoff.md を更新する。依頼主に、変えた所・検査の結果（成功／失敗／未実行）・見てほしい所を日本語で報告する。

公開・投稿・送信・購入・削除・権限の拡大は、この手順に含めない（その都度、明示の承認を得る）。
